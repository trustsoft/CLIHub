Lifecycle states

Busy → animated glyph; resolved → static glyph in the status tone (SuccessBrush / DangerBrush); idle (version known) → marker removed entirely.

Candidate glyph sets

The selected set drives every animated marker on this page. Braille sets are the OpenCode-style candidates; box-drawing and arc sets are single-codepoint alternatives if braille font coverage becomes a concern.

Implementation notes (WPF)

  • Fixed-width slot. The marker lives in its own TextBlock (or small BusyMarker control) with a fixed Width, so cycling glyphs never shift the label or neighboring layout. Keep it a separate control rather than concatenating text, so the literal stays in AgentVersionText-style constants and stays testable.
  • Animation. A single DispatcherTimer per visible control (or one shared ticker) at ~80 ms/frame. Pause when the control is not visible and honor SystemParameters.ClientAreaAnimation.
  • Label loses the ellipsis. The marker already says “busy”; keep the label plain (“Detecting”, “Checking”). Update AgentVersionText.Detecting and the UpdateButtonText states accordingly.
  • Completion. Swap the glyph, not the text pattern: ✓ in SuccessBrush, ✗ in DangerBrush — or drop the marker when idle.
  • Accessibility. Expose state via AutomationProperties (e.g. status text still “Detecting” / “Not installed”); the animation must never be the only signal, and screen readers should not announce frame changes.
  • Reduced motion. Static full-cell glyph (e.g. ⣿ or ●) instead of cycling when animations are disabled.
  • Fonts. Braille renders from Segoe UI Symbol / Cascadia Mono on Windows 10/11; verify in all three palettes and at high-contrast. Fallback sets above are single-codepoint and safe in any font.
  • Tray menu stays text-only. Native Win32 menus don't repaint per-frame; keep “Checking for updates…” as text there.
