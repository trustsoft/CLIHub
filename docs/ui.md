# UI: состав и поведение

Документ описывает ЧТО есть в UI и КАК оно себя ведёт, но не КАК отрисовывается.
Размеры, цвета, шрифты, компоновка — в UI-макете (CLIHub 2 UI) и в реализации.

## Принципы

- UI собирается из переиспользуемых примитивов.
- Поверхность (окно) состоит из зон и панелей.
- Элементы списков имеют идентичность (лого + подпись) и набор действий.
- Действия имеют состояние доступности, зависящее от данных.

## Примитивы

- **Поверхность (surface)** — отдельное окно приложения (Попап, Настройки, ...).
- **Панель (pane)** — область поверхности: заголовок + список.
- **Заголовок (pane title)** — подпись панели + кнопка меню `Actions`.
- **Список (list)** — упорядоченная коллекция элементов панели.
- **Элемент (item)** — единица списка: идентичность (лого, имя) + атрибуты + действия.
- **Действие (action)** — операция (run, resume, init, update, add, remove).
- **Меню (menu)** — всплывающий набор действий.
- **Футер (footer)** — нижняя зона: бренд, версия, системные действия.

## Поверхность: Попап

Назначение: быстро выбрать проект и запустить агента в нём.
Триггер (hotkey), фокус, закрытие — см. vision «Поведение попапа».

- Панель **Projects**: плоский список; элемент = лого + имя + путь; выбор одного
  (selected); меню `Actions`: Add, Remove.
- Панель **Agents**: агенты выбранного проекта; элемент = лого + имя + версия;
  действия run, resume; меню `Actions`:
  - **Update ▸** — подменю со всеми агентами;
  - **Init ▸** — подменю с агентами, не инициализированными в этом проекте.
- **Футер**: бренд + версия; действия: открыть папку данных приложения
  (где лежит `settings.json`), настройки, выход.

Доступность действий агента — см. vision «Формат плагинов агентов»
(run/resume — установлен + инициализирован; init — установлен + не инициализирован;
update — установлен; version — информация, не действие).

## Поверхность: Окно настроек

Назначение: редактирование настроек приложения (`settings.json`) и запуск
проверки обновлений по требованию. Открывается из tray-меню («Настройки»),
один экземпляр (повторный клик активирует открытое). Жизненный цикл: создаётся
при открытии с текущими значениями хранилища, закрывается крестом/«Отменой»
без подтверждения, несохранённые правки теряются.

- **Runtime по умолчанию**: выбор cmd / ps / wt.
- **Глобальный hotkey**: поле-захват (press-to-capture) — фокус, нажатие
  сочетания, каноническая запись (Ctrl+Alt+Space); чистые модификаторы
  игнорируются; Esc отменяет захват, не закрывая окно.
- **Проба агентов**: TTL (минут) и таймаут (секунд); пусто — дефолт.
- **Обновления**: флажок «Проверять при запуске» + кнопка «Проверить
  обновления»; результат — строкой в окне (последняя версия / готово к
  установке — установка через трей / недоступно вне установки / ошибка).
- **Сохранить**: валидация (TTL/таймаут > 0, hotkey разбирается) и запись
  `settings.json`; runtime применяется к следующим запускам, probe — к
  следующему раунду, hotkey — перерегистрацией сразу; если новая комбинация
  занята другим приложением — остальные значения сохраняются, hotkey
  откатывается, конфликт показывается в окне.

## Состояние реализации (снимок)

Выше описана целевая композиция. По факту уже реализовано:

- Панель **Projects**: лого + имя + путь; меню `Actions`: Add, Remove (флоу
  «Изменить»/лого-override ещё нет).
- Панель **Agents**: лого + имя + версия; действие run; список фильтруется по
  установленным агентам, а доступность run зависит от инициализации проекта.
  Действие resume и подменю `Update ▸` / `Init ▸` ещё не сделаны.
- Попап: hotkey-режим.
- Трей: иконка с пунктами «Настройки» и «Выход» (+ «Установить обновление»,
  когда апдейт готов).
- Футер: бренд + версия; системные действия — открыть папку данных,
  настройки (пока не подключена — кнопка неактивна), выход; статус — в центре
  футера.
- Окно настроек: реализовано без раздела «Проекты» (следующим изменением).
  Вход — из tray-меню; подключение кнопки настроек в футере попапа —
  вместе со следующим изменением.

Актуальное поведение зафиксировано в OpenSpec-специях (`openspec/specs/`).
