# Vision: CLIHub

## Суть

CLIHub — приложение-компаньон для Windows (10/11), которое даёт удобный запуск и обновление AI Agents CLI в папке проекта в один клик через hotkey-попап (иконка в system-tray — хост приложения).

## Проблема

Разработчик, работающий со множеством AI-агентов (Claude, Codex, Copilot, OpenCode и др.), вынужден вручную помнить команды запуска, обновления и инициализации каждого агента, а также открывать отдельный терминал нужного runtime (ps, cmd, wt) в папке проекта. Это рутинно, подвержено ошибкам и отнимает время.

## Цели

- Вести «реестр» проектов: рабочая папка, имя и лого.
- Запускать и обновлять агента в папке проекта в один клик в нужном runtime: ps, cmd, wt.
- Автоматически определять доступность агента на хосте и в проекте по заданным для каждого агента папкам/файлам.
- Строить список доступных агентов динамически (плагины) с учётом установленных на хосте.
- Предоставлять доступ через popup-окно по hotkey.
- Хранить все настройки в config.json.

## Не-цели

- Редактор кода или замена самим агентам/CLI.
- Полноценный терминальный эмулятор.
- Кроссплатформенность (macOS/Linux).
- Оркестрация/автоматизация выполнения задач агентами.

## Аудитория

## Технический фундамент (зафиксированные решения)

- **Платформа:** .NET 10 LTS, WPF (Windows-only — соответствует не-цели).
- **Tray-иконка:** H.NotifyIcon (иконка-хост; контекстное меню — только системные пункты).
- **Глобальный hotkey:** RegisterHotKey (P/Invoke), без внешних зависимостей.
- **Развёртывание:** framework-dependent (.NET Desktop Runtime как pre-requisite
  в инсталляторе). Подтверждено замером: FDD full-пакет ≈2.5 МБ и дельта кода ≈10 КБ
  против ≈70 МБ у self-contained.
- **Установка + автообновление CLIHub:** Velopack (per-user install, delta-обновления).
  Релизы — в публичном GitHub Releases репозитория `trustsoft/CLIHub` (Velopack
  `GithubSource`, токен клиенту не нужен).
- **Обновление агентов:** команды самих агентов (НЕ Velopack) — отдельный цикл.
  Два независимых контура обновления: CLIHub (Velopack) и агенты (команды).

## Поведение попапа (зафиксированные решения)

Попап открывается только по hotkey:

- **hotkey -> keyboard-launcher:** появляется по центру экрана (где курсор),
  забирает фокус. Закрытие: Esc, потеря фокуса (Deactivated), клик по пункту.

## Структура проекта (зафиксированные решения)

- **Слои:** Core (чистый .NET, без зависимости от WPF) + тонкий UI-слой.
  Вся логика в Core, покрывается тестами.
- **Core-сервисы:** LauncherCore (+ CommandBuilder, RuntimeResolver), PluginLoader,
  ConfigStore, ProjectRegistry, AgentDetector, LogoResolver, UpdateService.
- **MVVM-lite:**   ViewModel для попапа и окна настроек (`ObservableCollection` + `RelayCommand`);
  tray-иконка и hotkey — code-behind.
- **DI:** ручной composition root в App.xaml.cs; внешний DI-контейнер подключить позже
  при росте числа сервисов.

## Позиционирование и жизненный цикл окна (зафиксированные решения)

- **Источник координат:** GetCursorPos (экран под курсором).
- **Hotkey:** попап по центру экрана, где находится курсор.
- **Clamp:** Screen.FromPoint(cursor) -> WorkingArea; если попап не влезает у курсора —
  перекинуть и зажать в границах WorkingArea.
- **DPI:** Win32-координаты (px) конвертировать в DIP через
  PresentationSource.CompositionTarget.TransformFromDevice.
- **Окно:** один экземпляр (warm singleton); Hide(), а не Close(); создаётся один раз на
  старте.
- **WinForms reference:** включить UseWindowsForms ради Screen/Cursor.

## Формат плагинов агентов (зафиксированные решения)

**Расположение и загрузка:**

- Плагин = папка `plugins/agents/<folder>/` с фиксированным манифестом `agent.json`
  и ассетами (лого) рядом.
- Только встроенные плагины (в бандле приложения, обновляются Velopack);
  user-папки для переопределений нет (пока).
- `id` берётся из JSON и авторитетен; имя папки — лишь конвенция.
- `schemaVersion` (int) в каждом манифесте; неизвестные поля игнорируются;
  неподдерживаемая версия — skip + warning.

**Действия:**

- Фиксированный набор из 5 опциональных ключей: run, resume, version, update, init.
- Терминальные действия (run/resume/update/init) — shell-строка, встраивается в запуск
  терминала; command считается шелл-агностичным (exe + args).
- version — скрытый probe (argv), не терминальное действие; один прогон version-команды
  даёт и installed (exit code 0), и версию (первая строка stdout). Если version-действия
  в манифесте нет — фолбэк на PATH-проверку run-команды (без версии).

**Runtime:**

- Глобальный дефолт в config.json + опциональный per-action override в плагине.
- Разрешение: action.runtime (если != default) -> config.runtime -> дефолт.

**Детекция:**

- detect.host: probe (argv) — успешный exit code = установлен; результат кэшируется с TTL.
- detect.project: проверка путей (файлы/папки) в папке проекта — дёшево, вживую, без кэша;
  any-of (достаточно одного совпавшего пути); если пути не заданы — агент считается
  инициализированным везде.
- Набор доступных действий — производная от host/project статуса.

**Probe (гигиена и кэш):**

- При старте приложения — ленивый фоновый прогон probe, обновляет раздел `agents` в config.json.
- Настройки probe (TTL, timeout) — раздел `probe` в config.json.
- Запись в config.json — один раз после раунда, не по агенту.

## LauncherCore: запуск терминала (зафиксированные решения)

Отображение runtime -> форма запуска:

- cmd: `cmd.exe /k "<command>"`, cwd через WorkingDirectory.
- ps:  `powershell.exe -NoExit -Command "<command>"`, cwd через WorkingDirectory.
- wt:  `wt.exe -d "<cwd>" cmd /k "<command>"` (команда оборачивается в cmd, чтобы не
  зависеть от парсера wt и профиля по умолчанию).

- Окно остаётся открытым после команды (`/k`, `-NoExit`).
- PowerShell — `powershell.exe` (5.1) для v1.
- При отсутствии `wt` — fallback на ps/cmd + предупреждение.
- Терминальные запуски — fire-and-forget; probe — отдельный путь (скрытый argv,
  RedirectStandardOutput, ожидание с таймаутом).

## Окно настроек, config.json и обновление (зафиксированные решения)

**Окно настроек** — UI для config.json:

- открывается из tray-меню, один экземпляр (повторный клик активирует открытое);
- load при открытии -> правки -> «Сохранить» -> запись; валидация (TTL/timeout > 0,
  hotkey корректен);
- редактируемые разделы: runtime, hotkey, probe, update, projects;
- `agents` — машинный кэш, вручную не редактируется.

**Расположение:** `%AppData%\CLIHub\config.json` — стабильная data-папка, НЕ каталог
установки (Velopack заменяет каталог установки при обновлении). Эту папку открывает
иконка «folder» в футере попапа.

**Схема config.json:**

- `schemaVersion`, `runtime`, `hotkey` (по умолчанию `Ctrl+Alt+Space`)
- `probe` { ttlMinutes, timeoutSeconds }
- `update` { checkOnStartup }
- `projects[]` { id (guid), name, path, logo }
- `agents{}` — машинный кэш (hostInstalled, version, lastProbed)

**Обновление CLIHub:**

- фид: публичный GitHub Releases `trustsoft/CLIHub` (Velopack `GithubSource`).
- триггеры: старт приложения (фоново, не блокирует) + кнопка «Проверить обновления»
  в настройках (появится вместе с окном настроек);
- политика: check -> download в фоне -> нотификация в трее (только информирует) ->
  применить по явному действию пользователя — пункт tray-меню «Установить обновление»
  (ApplyUpdatesAndRestart). Авто-применение выключено (`SetAutoApplyOnStartup(false)`):
  без действия пользователя обновление не ставится;
- вне Velopack-установки (dev-запуск) и при ошибках сети проверка молча пропускается,
  повтор — на следующем старте.

## Реестр проектов и лого (зафиксированные решения)

**Запись проекта:** id (guid), name, path, logo.

- name по умолчанию = имя папки, редактируется;
- logo = авто-резолв + опциональный ручной override;
- флоу: «Добавить» (folder picker) / «Изменить» / «Удалить» (файлы на диске не трогаются);
- валидация: path существует и является папкой, нет дубликата path, name непустой.

**Резолв лого** (единый механизм, разные корни):

- корень для агента = папка плагина `plugins/agents/<folder>/`;
- корень для проекта = корень папки проекта (плоско);
- приоритет: logo.(png|ico) -> icon.(png|ico) -> favicon.ico -> default-logo; внутри
  пары расширений png раньше ico;
- ручной override проекта (`project.logo`) побеждает цепочку, когда файл существует:
  относительный путь резолвится от корня проекта, абсолютный — как есть; битый override
  молча падает в авто-цепочку.
